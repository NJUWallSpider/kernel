\chapter{文件边界、API 与资源}
\label{ch:loader}

\section{完整文件验收}
CLI 用法固定为：
\begin{lstlisting}
rpx verify source.mcm target.mcm proof.rpx
\end{lstlisting}
不接受额外证明路径、Request 文件或关系选择参数。MPS/LP 须先精确导入 MCM：
\begin{lstlisting}
rpx canonical source.lp source.mcm
rpx canonical target.lp target.mcm
\end{lstlisting}
导入不使用浮点容差；最大化目标整体取负，保留常数、界、整数声明和全部约束。
支持的原始文件方言分别见 \code{docs/MPS_V1.md} 与 \code{docs/LP_V1.md}；
不支持的构造必须拒绝，不得静默丢弃。

Rust 纯验证函数接收两个 Model、一个 Certificate 及 Limits。
文件/字节接口分别为 \code{api::verify_paths} 与 \code{api::verify_bytes}；
文件 I/O 和计时位于外层，数学执行不读取时钟或环境。
结果 status 为 VERIFIED、INVALID、RESOURCE\_LIMIT 或 IO\_ERROR，CLI 分别退出 0、2、3、4。
只有 VERIFIED 表示完整 MI 优化等价。资源拒绝是未完成检查，不表示不等价。

\section{编写接口}
Python 的 Proof 固定拥有 forward 与 reverse 两个 DirectionBuilder。
每个方向由 map、步骤和完整收尾组成；作者可用 plan 查看内核生成的义务，用 complete 检查遗漏。
计划、扩展布局准备、汇编和序列化都不授予 VERIFIED；最终仍由内核执行两棵证明树。
编写器支持稀疏精确表达式、行组合、舍入、分支与五种联合构造，但不搜索 reformulation。

交付文件必须重新读入并与已证明模型精确比较。链式工作流逐阶段验证同一固定目标，
并检查相邻模型和文件摘要；链不是内核中的第三类证明对象。

\section{资源与诊断}
路径输入每文件上限为 512 MiB，独立于 codec 的 1 GiB 上限。
RPA 12 文本输入上限为 256 MiB；指令、表达式项与列表项合计最多 20,000,000 个节点；
嵌套深度最多 128。规范反汇编输出同样受 256 MiB 上限约束。
有理数运算中间结果受 65,536 位上限约束；格式幅值另受 1700 字节上限约束。
模型名称最多 1024 字节，须非空 ASCII、无控制字符且在各自命名空间唯一。
更多精确边界和导入限制见 \code{docs/API.md} 与格式规范。

work 是确定性收费策略，不等同于 CPU 指令数或物理内存上界。
work、live-facts、depth 参数只可控制资源，不可删除数学义务。
方向、步骤、义务诊断是尽力报告的位置；统计量与计时不参与数学接受条件。
