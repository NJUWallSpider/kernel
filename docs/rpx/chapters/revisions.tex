\section{冻结检查点}
\begin{enumerate}
\item 确认两个 profile、目标方向、offset 与调用者 policy，并证明 contract 定理的前提完整。
\item 接受或修订 branch 事务、三态 mapping、混合定义拒绝、obligation 交集及 root false 的规则。
\item 确认 FactId 编号、scope-local DROP、静态 YIELD 的 ExprView 与 exact proposition equality。
\item 确认全部 28 个 opcode 的字段、长度、flags、aux、类型前提与错误条件；不存在未定义的核心 mnemonic。
\item 确认 ScalarPool、ExprPool、Map、Header、Directory 的编码，特别是 count、padding、overflow 和 mandatory/optional 行为。
\item 逐条审阅第\ref{ch:examples}章三个完整双向证明，使每个成功路径都有完整 mappings 和 obligations。
\item 为 wire format 准备 Header、ScalarRef、ScalarPool、每个 opcode、nested split 与 malformed 文件的 golden vectors。
本手册给出的若干向量是起点，不能冒充覆盖全部 opcode 的测试套件。
\item 为接受结果、unsupported、resource limit 和 I/O failure 定义公开接口与诊断约定。
\item 确认核心规范不借助 proof search、浮点容差或隐藏 theorem 获得接受结果。
\item 所有接受的修订同步到示例与文档，再将草案状态改为 frozen v0.1；冻结后不改写已发布字段含义。
\end{enumerate}
