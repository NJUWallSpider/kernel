\chapter{完整证书示例与验收案例}
\label{ch:examples}

本章的前三份证书都是当前 CLI 可执行的完整双向程序。每份包含两份完整 LP 模型、一份严格 JSON RPA 和调用者独立提供的 request；正文直接引用仓库文件，没有省略的变量、模型行、证据或摘要占位值。它们采用已冻结的 RPA/RPX 1。MCM 和 RPX 由现有命令生成到临时目录，证书不含授权接受的模型 hash。

\section{复核入口与结果}

从仓库根目录执行：
\begin{lstlisting}[caption={重建、回读与负例复核}]
cargo build -p kernel-core --release --locked
python3 tools/check_rpx_manual.py --kernel target/release/rpx --out docs/.build/manual-examples.json
\end{lstlisting}

脚本对每份示例重新 canonicalize 两份 LP、assemble、verify，再 disassemble、assemble 并要求 RPX 字节相同、再次 verify。它还独立运行三种逻辑变异和一次零 work 预算检查。2026 年 10 月 13 日当前源码重建后的复核全部通过；完整 receipt 在 \code{docs/rpx/examples/verification.json}，记录实际可执行文件与输入的 SHA-256、计数和错误报告。SHA-256 仅用于复核产物身份。

\section{示例 A：删除冗余上界行}

\subsection{完整模型与调用者要求}
Source 为 $0\le x\le1$，有 $x\le1$ 和 $x\le2$ 两行；Target 为 $0\le y\le1$，只保留 $y\le1$。目标都恒为零，变量均连续。LP 的首次出现顺序使唯一坐标编号为 0，Source 行编号为 cap=0、loose=1。

\rpxlisting[caption={A：完整 Source LP}]{rpx/examples/redundant/source.lp}
\rpxlisting[caption={A：完整 Target LP}]{rpx/examples/redundant/target.lp}
\rpxlisting[basicstyle=\scriptsize\ttfamily,caption={A：独立 caller request}]{rpx/examples/redundant/request.json}

request 明确要求两方向目标相等、坐标投影相等和互为 affine inverse。因此该例确立完整可行集的目标保持双射；不能从仅有双向可行性的证书推测出这些额外关系。

\subsection{完整 RPA 与核验}
\rpxlisting[basicstyle=\scriptsize\ttfamily,caption={A：完整 RPA 1 证书}]{rpx/examples/redundant/proof.rpa}

Forward 和 Reverse 都取恒等 map。Reverse 的 Lin 定义
\[
\operatorname{LE}\bigl((y-1)-1\bigr)=\operatorname{LE}(y-2),
\]
所以 Source 的 loose 行也得到精确匹配。每个 Return 按 kernel 顺序列出 bounds、rows、objective、projection 和 inverse 证据；Forward 有六个，Reverse 有七个。没有整数性义务，也没有隐含不存在的行下界。

单独运行本例的真实命令为：
\begin{lstlisting}[caption={A：从 LP 到 VERIFIED}]
mkdir -p docs/.build/manual-redundant
target/release/rpx canonical docs/rpx/examples/redundant/source.lp docs/.build/manual-redundant/source.mcm
target/release/rpx canonical docs/rpx/examples/redundant/target.lp docs/.build/manual-redundant/target.mcm
target/release/rpx assemble docs/rpx/examples/redundant/proof.rpa docs/.build/manual-redundant/proof.rpx
target/release/rpx verify docs/.build/manual-redundant/source.mcm docs/.build/manual-redundant/target.mcm docs/.build/manual-redundant/proof.rpx docs/rpx/examples/redundant/request.json
\end{lstlisting}

最后一条返回 \code{VERIFIED}，退出码 0；前面的成功状态分别为 \code{CANONICALIZED} 和 \code{ASSEMBLED}。

\section{示例 B：利用等式消去一个变量}

\subsection{完整模型与调用者要求}
Source 的 $x_0,x_1\in[0,1]$ 满足 $x_0+x_1=1$，目标 $f_S=x_0$；Target 的 $y\in[0,1]$ 无行，目标 $f_T=1-y$。保留 $x_1$，重建 $x_0=1-y$。目标常数 1 必须参与 canonicalization 和证明。

\rpxlisting[caption={B：完整 Source LP}]{rpx/examples/elimination/source.lp}
\rpxlisting[caption={B：完整 Target LP}]{rpx/examples/elimination/target.lp}
\rpxlisting[basicstyle=\scriptsize\ttfamily,caption={B：独立 caller request}]{rpx/examples/elimination/request.json}

两个 projection 数组分别要求 $y=x_1$ 和 $x_1=y$。两个 inverse 字段要求恢复全部输入坐标，不仅是被保留坐标；它们在不同维数的可行集上仍可成立。

\subsection{完整 RPA 与核验}
\rpxlisting[basicstyle=\scriptsize\ttfamily,caption={B：完整 RPA 1 证书}]{rpx/examples/elimination/proof.rpa}

Forward 的目标差与第一个 inverse 坐标差都是
\[
(1-x_1)-x_0=-(x_0+x_1-1).
\]
\code{Local:0} 是由实际 input equality 的负倍数推出的 EQ，不能替换为 \code{Exact}。Forward 有六个 obligations：两个 bounds、目标、投影、两个 inverse 坐标。Reverse 的四个 bounds 归一化依次为 $y-1,-y,-y,y-1$，分别使用 Target 的 upper、lower、lower、upper；等式行、目标、投影和一个 inverse 坐标随后都精确恒为零，共八个 obligations。

复核脚本调用与示例 A 相同的 \code{canonical}、\code{assemble}、\code{verify} 命令，参数换为 \code{rpx/examples/elimination/} 的四份完整输入；独立 request 始终是该目录的 \code{request.json}。当前实际结果为两方向 \code{VERIFIED}、14 obligations。

\section{示例 C：分段绝对值 mapping}

\subsection{完整模型与调用者要求}
Source 的 $x\in[-1,1]$，Target 的 $y\in[0,1]$，都没有模型行，目标都为零。Forward 取 $y=|x|$，Reverse 取 $x=y$。request 只要求双向可行性和目标相等，不要求 projection 或 inverse：$x$ 与 $-x$ 可能映到同一 $y$。

\rpxlisting[caption={C：完整 Source LP}]{rpx/examples/piecewise/source.lp}
\rpxlisting[caption={C：完整 Target LP}]{rpx/examples/piecewise/target.lp}
\rpxlisting[basicstyle=\scriptsize\ttfamily,caption={C：独立 caller request}]{rpx/examples/piecewise/request.json}

\subsection{完整 RPA 与核验}
\rpxlisting[basicstyle=\scriptsize\ttfamily,caption={C：完整 RPA 1 证书}]{rpx/examples/piecewise/proof.rpa}

Forward 的 \code{Split} 两支分别假设 $x\le0$ 和 $-x\le0$，覆盖所有实数。left 的完整 Return 定义 $y=-x$，其 lower 是 assumption，upper 是 Source lower $-x-1\le0$。right 定义 $y=x$，lower 是 assumption，upper 是 Source upper。两支各自提供同一个完整三项检查清单；Split 后没有继续执行或汇合不完整 map 的代码。

零点同时满足两支条件，两支给出的值都为零。当前 verifier 核验两个完整子树；此证书与 CLI 不提供 D0 中建议的独立数值解重建器或 \code{SEALED_PIECEWISE} 状态。Reverse 用 Lin 从 $-y\le0$ 推出 $-y-1\le0$，再直接证明上界和目标。当前结果为 \code{VERIFIED}、九个 obligations、一个 branch point。

\section{完整 corpus：严格改进与条件最优投影}

小示例不替代完整模型的实际证书。\code{cases/test36/} 的 RPA 10、两份 MCM 和独立 request 绑定真实 Source 的 37,816 个坐标与 37,617 行，以及真实 Target 的 37,616 个坐标与同样行数。令 $P$ 为全部 200 个原始非负连续 terminal 的和。完整 request 同时要求：
\begin{enumerate}
\item 所有 Source MI 可行点有完整 Target MI 像，目标 NonIncreasing。
\item 所有 Target MI 可行点有完整 Source MI 恢复，目标 Equal，并保留全部 37,616 个 retained 坐标。
\item 在 caller 明确绑定的原始半空间 $P\le0$ 内，Source 到 Target 的完整 map 目标 Equal，并保留上述全部坐标。
\item 每个满足 $P>0$ 的 Source MI 点都有一个完整 Source MI 严格改进。
\end{enumerate}

第四项迫使任何已达到的 Source minimizer 满足 $P=0$，因为原始 bounds 保证 $P\ge0$。第三项随后适用于这个 minimizer，建立它本人的 retained projection；第二项恢复 Target minimizer。仅有第四项不能证明 retained projection，另取一个更优点可能改变这些坐标。条件 claim 的 \code{input_halfspace} 与 improvement 的 \code{positive} 都精确绑定全部 200 个 original terminal；删项、反向或换 caller request 均不能代表同一结论。

条件 proof 在完整原始模型末尾追加 $P\le0$，由原始 lower bounds 和 EqPair 得到 $P=0$，再证明每个 terminal 为零；它没有用外部裁剪模型替代输入。改进 proof 分别使用 predicate margin $4850P$ 和 constant margin 858。连续 terminal 不借用整数 guard；保存的 $P=1/4850$ 可行控制点说明正 terminal 仍然可能 Source-feasible。

这确立最小值保持和所有最优点的 retained projection，不确立无条件可行集投影相等、LP 等价、全可行集双射或某个指定数值最优值。完整 certificate 的 529,636 obligations 与 448,596,660 work 已复核；此前缺少条件投影的成功请求仍保存在历史目录，不能冒充当前完整要求。来源为 \code{cases/test36/PROJECTION_REVIEW.md} 和 \code{audit/TEST36_COMPLETE_REVIEW.md}。

\section{完整 corpus：联合 subflow 与 point contracts}

\code{cases/test58/} 的完整 Source 有 2,500 个变量、1,750 行，Target 有 607 个变量、785 行。Forward 对所有 Source MI 点给出完整 Target MI 非增目标像，Reverse 对所有 Target MI 点给出完整 Source MI 等目标恢复。两方向保持最小值并提供恢复；不要求 LP 等价或全可行集双射。

其 V10 \code{SubflowLift} 同时产生 180 个节点、606 条有向弧的一个共同流，逐弧不超过给定原始流及总 demand 82，并保留所有所需节点 balance。它与 V4 FlowLift 的逐弧总流相等结论不同，也没有把独立局部流见证拼成未经检查的全局 tuple。所有 old-scope premises 先被核验，再进入同一 generated extension，最后核验完整 Target map 的全部 bounds、integer designations、rows 和 objective。联合存在性仍依赖 \code{docs/SUBFLOW_DRAFT.md} 的可信 builder 引理；完整 child obligations 不会独立证明这条引理。该实际完整请求复核为 8,448 obligations、2,029,879 work；八个保存的负例覆盖缺失 balance、越界 old-scope 引用和错误反向恢复。

\code{cases/test71/} 同时核验整数双向 identity/inverse、Target LP 到 Source LP 的完整 inclusion、严格性点，以及 Source integer 与 Target LP 的全局 lower bound $-12$ 和达到该值的完整点。因此可报告这些精确最优值及严格 LP strengthening；整数等价并不意味着 LP 等价。完整 strictness 点每个坐标为 $1/56$，违反实际 Target 新行 $\sum x\le12$。

\code{cases/test62/} 保留原有两方向整数目标保持和 V7 complete-domain bijection，再以 V10 \code{ImageExclusion} 核验 4,500-coordinate Source LP 点和全部 500 个 Target image expressions。检查到实际 Target 违反便成立；它不要求或证明 Source LP 的全局映射 inclusion。\code{cases/test18/}、\code{cases/test19/} 的完整 fiber refutations 则展示第三类 claim，定义和 fresh-scope 边界见 \code{docs/FIBER_POINT_V6.md}。

\section{实际案例的可重复入口}

上述五份完整实际 certificate 已使用当前重建 CLI 再次验证，命令和完整非压缩 reports 保存于 \code{docs/rpx/examples/corpus-verification.json}。这里的单次时钟结果仅作功能诊断，不作性能比较。已有产物可直接复核，例如：
\begin{lstlisting}[caption={完整 test36 与 test58 的当前 verifier 入口}]
target/release/rpx verify cases/test36/source.mcm cases/test36/target.mcm cases/test36/proof.rpx cases/test36/request.json
target/release/rpx verify cases/test58/source.mcm cases/test58/target.mcm cases/test58/proof.rpx cases/test58/request.json
\end{lstlisting}

若要从 immutable corpus 文件重新导入、重组完整 RPA 并核对交付元数据，使用现有 delivery checker 的真实命令：
\begin{lstlisting}[caption={完整模型与证书的交付复核}]
python3 tools/check_delivery.py --case test36 --case test58 --case test62 --kernel target/release/rpx --out docs/.build/manual-delivery.json
\end{lstlisting}

该工具与 preparation/receipt 都是复核编排。最终接受仍由完整实际模型、独立 request 和 RPX 进入 kernel 得出。当前 81/81 完整实际案例、11 个 family 与 83 次成功调用的交付结论来自 \code{audit/FINAL_DELIVERY_REPORT.md} 及 \code{audit/acceptance.json}；不同日期的冻结 checkpoint 和历史 scope 缺失记录保留其原始含义。
