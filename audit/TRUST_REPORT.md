## Exact model and statement binding

The MCM records contain every domain flag, lower/upper bound, row expression and side, objective coefficient and constant. MPS binary variables become integer coordinates intersected with `[0,1]`; continuous coordinates remain real. Relaxation claims remove integrality while retaining all finite bounds. Unsupported MPS/LP dialect features are not silently approximated or imported by a solver. Dialect semantics are specified in [MPS_V1.md](../docs/MPS_V1.md) and [LP_V1.md](../docs/LP_V1.md). The added `lp.rs` belongs to the same trusted boundary. `audit/lp_parse_sweep.json` records ALL_FIELDS_EQUAL on all three actual corpus LP inputs against an independent Python Fraction parser and separate MCM decoder; 160 generated exact oracle models and 2,000 ASCII mutations add bounded evidence. Import equivalence does not by itself prove the reformulations.

RPX facts come from actual input-model values. Every output variable must have one common-tuple map expression; every finite bound, required integrality, row side, objective relation, coordinate/affine projection and requested inverse composition becomes a verifier-generated obligation. The certificate cannot choose a subset or replace the expression being proved. File names and SHA-256 inventory metadata aid provenance but do not authorize acceptance. In particular, no identity or row-equality fast path accepts a hash collision as equality.

The caller supplies requested mapping, point and bijection claims separately; certificate claims must exactly match them. V3 objective lower bounds generate an additional exact input-objective inequality at every Return. Complete rational point witnesses independently establish feasibility/attainment, V3 strict LP inclusion under a complete coordinate permutation, or V6 strict partial affine observation inclusion by full-fiber LP refutation, after all referenced directional claims have passed; [POINT_V3.md](../docs/POINT_V3.md) states the exact restrictions. EQ and LE objectives are distinguished. Bidirectional LE maps prove equality of extended infima, including empty feasible sets and nonempty unbounded objectives. EQ maps preserve objective levels. Projection equalities and inverse compositions are separate obligations; an optimum-only result must never be reported as original-coordinate equality or bijection. An empty source only vacuously proves its own direction; the other requested direction still executes.

## Soundness argument and code correspondence

### Lift inference remains inside the trusted boundary

For each lift, the required statement is existential: for every old point x
satisfying the actual current model M and the checked premises P, there exists
one simultaneous tuple z satisfying the generated extended model E(x,z), with
the old coordinates, domains, rows and objective preserved. The statement is
`M(x) and P(x) => exists z. E(x,z)`, not that arbitrary new coordinates satisfy
the generated rows.

The Rust builders implement both P and E and are trusted inference code.
`Context::check_fact` proves the returned P in the old scope; `Model::validate`
checks structural validity; the child proves its obligations conditional on E.
None independently proves this existential statement or validates the builder
against its mathematical specification. An incorrectly overconstrained or empty
extension could invalidate soundness despite all three checks. The mathematical
arguments, implementation reviews and independent finite test oracles are
different kinds of evidence; they are not a machine-checked correctness proof
of the Rust implementation. Earlier wording that a builder was "not a proof
authority" referred only to its inability to discharge premise references and
must not be read as excluding it from the trusted computing base.

The subsequent shared-mechanics extraction removes 401 net source lines across
seven construction modules, including its new shared module. Rule-specific
premises, generated constraints and domains remain in the individual modules;
this does not add an independent lemma checker or reduce the mathematical
rules being trusted. `audit/builder_support_extraction.json` binds the before/after
sources, both 210-test runs, 576 full-output differential constructions, 456 bad
models, 1,728 exact work-boundary calls per implementation and 48 complete actual
case replays. Every replay retains identical mathematical statistics and every
RPA reassembles to its existing RPX bytes. The internal baseline contains the
unfrozen objective-level draft; this evidence does not freeze that protocol.
Development replay times are not a speedup claim.

[SEMANTICS_V1.md](../docs/SEMANTICS_V1.md) specifies the core propositions, check ordering and directional contracts. [FORMAT_V1.md](../docs/FORMAT_V1.md) specifies exact wire data. [FORMAT_V2.md](../docs/FORMAT_V2.md) gives the local-Cases and antisymmetry statements, version boundary and implementation correspondence. The initial design audit is [draft_review.md](draft_review.md).

The common inductive invariant is: every live fact holds for every input point satisfying the actual input model and the current path assumptions. Static row/domain facts establish this invariant. Exact linear combinations, sign-restricted inequality multipliers, integral INT coefficients, equality-as-zero transfer, mathematical rounding, and antisymmetry preserve it. A contradiction requires a variable-free positive LE or nonzero EQ.

At a full Return, all output variables use one jointly defined affine tuple in the current input/extension coordinates. V4 FlowLift preserves every old input coordinate and objective, then simultaneously introduces a jointly feasible commodity-flow tuple after all premises pass. A finite common-source path extraction followed by assigning all residual circulation to the first commodity proves existence over real inputs, including loops and disconnected cycles. The child checks the actual output model completely; no existential choices from separate rows are joined. V5 IntervalLift similarly introduces all independent choices jointly, using a maximum lower/minimum upper/zero construction after every pair premise. Coordinate and affine observations are validated against original dimensions; newly introduced variables remain continuous, and affine inverse contracts reject either non-affine terminator. Exact expression matching against complete output obligations proves this tuple feasible and establishes the requested objective/observation identities. Full Split branches cover the current domain and each independently provides a complete mapped result or contradiction. They have no post-split continuation needing a partial obligation join.

V2 Cases covers the current domain in the same way but exports only one identical fixed parent fact. Its children have no output maps and cannot discharge output obligations. Each child executes from its own isolated view of parent facts, so no sibling-local premise or local DROP leaks. A child may return a checked common proposition or an exact contradiction. This rule cannot combine incompatible existential witnesses because its conclusion is one universally true input-coordinate fact. The actual test88 proof uses these local lemmas while retaining complete root maps.

V1/V2 register IDs can be reused only after DROP and a new checked definition; a live ID cannot be overwritten. References between DROP and redefinition fail. Dropping a parent fact in a child affects only the child's visible register file. These are intentional differences from the earlier D0 draft's SSA proposal and are documented in the versioned format.

The rare Cases payload is now boxed internally: the rebuilt V6 Step slot is 96 bytes on this host instead of 208, with an indirect 208-byte CasesStep. The exact serde object and wire fields are unchanged. All 147 core tests passed and all 11 actual RPA files reassembled to byte-identical RPX; [BOXED_CASES_REVIEW.md](BOXED_CASES_REVIEW.md) records the independent merge review and receipts. The layout change alone retained whole-live branch copies and did not certify the resource-limited test18 candidate; the subsequent scope change is recorded separately below.

The V6 scope port uses an immutable parent chain with local definitions and deletion masks. A visible map is the local map overlaid on the parent's visible map with locally dropped IDs removed. This preserves DROP/reuse, masks older bindings after a second DROP, and prevents sibling writes from leaking. Cases borrows the same parent in two separate scopes; a terminal Split borrows for its left child and consumes its unchanged state for the right child. Extensions preserve the original coordinate prefix and move the same state into their sole child. Both mapping and LP-refutation roots begin with fresh facts and assumptions; refutation endpoint restrictions remain checked before steps. [SHARED_SCOPE_REVIEW.md](SHARED_SCOPE_REVIEW.md) records the independently audited invariant and copied-map oracle, and `scope_v6_merge.json` records the exact port, hashes and validation. This changes internal storage and work accounting, with no RPX/RPA version or mathematical rule change. The merged production tree passed all 154 core tests, including seven scope regressions and 128 independent copied-map state trees (127,072 operations). The broader workspace run completed those core tests but its Python-wrapper test could not start because the host lacked `libpython3.13.dylib`; this environment failure is preserved in the merge receipt.

For V7, menu premises force A in {0,1} and integral I between 0 and K*A. The all-zero vector when inactive and the unit vector at I when active establish simultaneous menu existence. Complete output obligations remain ordinary checked obligations. Bijection acceptance is separate: full F(G(t))=t gives surjectivity, while the paired domain contains exactly two actual source points sharing every F coordinate. Proving all source coordinates equal there establishes injectivity. Together these imply both inverse identities for the complete actual sets, including any continuous auxiliaries. Existing affine inverse restrictions remain intact. New roots use fresh state and the remaining request budget.

The optimized sparse accumulator uses integer coordinate keys and exact BigRational arithmetic. Hashes select storage buckets only. Each product, accumulated coefficient and constant is checked; cancellation removes only exact zero, and final terms are sorted by coordinate. All numerical equality remains exact. Shared storage does not substitute for proof and no modular/random filter is used for acceptance.

## Resource and audit limitations

The codec bounds byte length, cumulative counts, rational magnitudes, names and combined block/derivation depth. The verifier bounds sparse work, live facts and nesting. Every loaded and constructed proof expression is canonical and checked against model coordinate and arithmetic limits. These limits can reject mathematically valid larger inputs as RESOURCE_LIMIT; they never justify approximate acceptance. Numeric parsing, serialization and in-memory arithmetic have different documented maxima, so a representable parsed rational can still exceed the serialization budget.

Residual engineering limits remain:

- Work counters are explicit sparse-operation budgets, not a hard wall-clock timer or exact bigint bit-complexity meter.
- Global byte/count budgets are not a process-wide peak-memory guarantee. Some expression/model `Clone` paths and library internal big-integer/JSON allocations use the standard allocator; not every allocation can return a structured failure before OS termination. Most explicitly reserved vectors/maps use `try_reserve`.
- MCM/RPX currently materialize owned data rather than streaming or memory mapping. Branch scopes share immutable ancestors and retain hidden facts until the owning scope ends. Logical peak-live counts therefore do not measure physical memory; local changes, deletion masks and retained ancestor facts also occupy storage.
- The generic shared expression/mapping DAG, dedicated batch format, and numeric reconstruction tool are not implemented. Plotkin, common-source FlowLift, independent IntervalLift, optional MenuLift and SignedLift are explicitly versioned static theorems, not general combinatorial search or arbitrary existential proof capabilities. A dynamic theorem registry is also absent, but arbitrary runtime proof plugins are not a delivery requirement or a proposed remedy. Expression sharing and batch representation address repeated representation/computation; they do not themselves establish the existence lemmas. Core affine maps, local branching, common-source real-flow extension and independent interval extension do not imply compact proofs for all transformations. Both text importers support defined subsets, not every solver-specific MPS/LP dialect.
- Parser mutation tests and exact oracle tests are bounded regression evidence. They are not exhaustive fuzzing, a second independent complete verifier, or a formal implementation proof.
